# Антиплагиат HSE

## Реализованный функционал

| Функционал                     | Реализация                                                                  |
|--------------------------------|-----------------------------------------------------------------------------|
| Добавление файла               | `Api Gateway -> File Storage Service (Controller, Service, Repository)`     |
| Получение файла по ID          | `Api Gateway -> File Storage Service (Controller, Service, Repository)`     |
| Анализ файла по ID             | `Api Gateway -> File Analysis Service  (Controller, Service, Repository)`   |
| Получение картинки облака слов | `Api Gateway -> File Analysis Service  (Controller, Service, Repository)`   |

## Примененные архитектурные принципы

### Clean Architecture

| Принцип                      | Реализация                                     |
|------------------------------|------------------------------------------------|
| Слоистая архитектура         | `model`, `controller`, `service`, `repository` |
| Зависимости внутрь           | Model не зависит от других слоев               |
| Изоляция бизнес-логики       | Вся логика в Model и Service слоях             |

### Микросервисная архитектура

| Модуль/Сервис         | Ответственность                                                                 |
|-----------------------|---------------------------------------------------------------------------------|
| Api Gateway           | Принимает запросы со стороны клиента и перенаправляет в необходимые сервисы     |
| File Storage Service  | Отвечает за хранение/получение текстовых файлов, управление                     |
| File Analysis Service | Отвечает за анализ текстовых файлов, в том числе обращение к Word Cloud Service |
| Word Cloud Service    | Обращение к Word Cloud API, получение картинки облака слов                      |
| Common                | Общие сущности, например FileNotFoundException...                               |


## Технологический стек

- **Язык**: Java 17
- **Фреймворк**: Spring Boot 3
- **База данных**: PostgreSQL

## Как запустить проект

1. Клонировать репозиторий
2. Запустить Docker Desktop(Docker daemon)
3. Из корня проекта выполнить `docker compose up --build`
4. Протестировать через Postman (Импортировать test/AntiplagHSE.postman_collection.json из корня проекта в Postman)
5. Можно воспользоваться файлом test/1.txt в качестве тестового текстового файла.


## По критериям

- Реализация основных требований и сценариев(4). Все сценарии реализованы в соответствии с ТЗ(картинки в конце)
- Функциональность распределена по микросервисам(см. таблицу `Микросервисная архитектура`), ошибки Service Unavailable обрабатываются корректно (30 секунд таймаута)
- Реализована коллекция Postman с 4 сценариями
- Код чистый и модульный (см. `Архитектурные принципы`)
